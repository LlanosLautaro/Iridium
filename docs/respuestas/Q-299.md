Una distinción importante: los efectos deberían ser reutilizables independientemente de los componentes. Por ejemplo, pulse no debería pertenecer exclusivamente a un marcador de mapa. También podría utilizarse en una luz de estado, un botón o una alerta.

4. Un prompt para enseñárselo a Claude
Te dejo una instrucción que podrías incorporar a las reglas de tu Design System o convertir en una skill.

FUI & Interface Motion Design
Objective
Develop a reusable visual behavior system inspired by futuristic video game interfaces, science-fiction HUDs, spacecraft control panels, tactical systems and fictional user interfaces (FUI).

The goal is not simply to make interfaces look futuristic. Interfaces should feel like sophisticated technological systems that are alive, responsive and continuously communicating their operational state.

Design principles
Motion must communicate information, state, interaction or system activity.

Visual effects must be reusable and independent of individual components.

Animations should be subtle by default, with stronger effects reserved for important events.

Avoid excessive neon, indiscriminate glowing and meaningless decorative animations.

Prioritize visual coherence, timing consistency and smooth transitions.

Motion vocabulary
Implement reusable motion primitives:

Pulse: periodic changes in opacity, scale or luminous intensity.

Glow: controlled light emission around elements.

Blink: intermittent visibility for alerts and status indicators.

Radar Sweep: rotating scanning sectors.

Light Sweep: moving luminous gradients across surfaces.

Rotating Reticles: independently rotating concentric rings and markers.

Scanlines: horizontal scanning patterns.

Glitch: controlled digital distortion.

Data Stream: animated telemetry and continuously updating readouts.

Entrance / Exit: transitions for appearing and disappearing components.

Component behavior
Components should support consistent interaction states:

Idle

Hover

Focus

Active

Selected

Processing

Success

Warning

Error

Disabled

Different states should have distinct visual feedback where appropriate.

Motion tokens
Centralize animation properties:

Duration

Delay

Easing

Iteration

Direction

Intensity

Glow intensity

Pulse amplitude

Animations must be configurable through design tokens rather than hardcoded independently in every component.

Technical requirements
Prefer CSS animations and transitions for simple effects.

Use SVG for radial indicators, reticles, scanning arcs and geometric animations.

Use Canvas or WebGL only when the complexity justifies it.

Support reduced-motion preferences.

Avoid unnecessary continuous animations that consume resources.

Ensure effects work across the entire design system without introducing inconsistent implementations.

Expected result
Create a cohesive, extensible FUI motion language that can be applied to buttons, indicators, maps, dashboards, panels, navigation elements and complex interactive components.

The system should make interfaces feel like functional instruments from a technologically advanced civilization, rather than conventional websites with neon decorations.
